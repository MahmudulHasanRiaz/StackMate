# ADR-0011: Storage driver strategy (Local vs R2) + media library

- **Status:** Accepted (implemented 2026-11-18, media batch — owner order 2026-11-18 16:06–16:08 +06, Roman Bangla: "FULL FEATURED, UI most optimized, wow level; everything organized, usable + manageable; all file types; EVERYWHERE in the app where an upload exists, a direct media picker from the library must be there — pick from the library AND upload new, easily, from the same place")
- **Context:** File uploads existed in exactly two places (proved by parent inventory 2026-11-18): the favicon upload (Settings → General) and the payment-evidence upload (Payment Review) — both writing private objects to the R2 bucket `stackmate-private-assets` via `apps/api/src/platform/storage/r2.ts`, with magic-byte validation for PNG/JPEG/WEBP/PDF and a 5 MB evidence cap. There was no media library, no Local storage driver, and no storage-driver setting. The longer direction (owner, 2026-11-18) requires Docker/VPS deployment fully Cloudflare-free, with a selectable Local/R2 storage driver — while Postgres stays primary and the staging default stays R2. The owner said "whatever" for file types, but Security §4.9 requires MIME + magic-byte validation for every accepted type, so an open-ended accept-all is not shippable.

- **Decision 1 — Storage driver abstraction (`apps/api/src/platform/storage/driver.ts`, `local.ts`):** One interface, `StorageDriver` (`put/get/delete/exists`, `name`); `R2StorageDriver` wraps the existing R2 binding; `LocalStorageDriver` is plain files under a root directory, loaded via DYNAMIC `import("node:fs/promises")` only — never a static `node:fs` import, so the Worker bundle never pulls node:fs in. On Workers the dynamic import throws and the driver refuses with an honest 503 (`INTERNAL_ERROR`, "Local storage is not available in this runtime… Select the R2 driver in Settings → Storage") — never silently stores nowhere. `resolveStorageDriver(deps, driverName?)` picks the driver: explicit override first (media rows carry their own driver), else the `storage_settings` row, default `r2`. Fail-closed, same rule as payment evidence / favicon before it: in staging/production the R2 driver requires the REAL bucket binding — an in-memory bucket there refuses uploads (503), it does not silently store bytes that vanish on restart. Local keys are hardened (no absolute paths, no `..`, no backslash); the root resolves settings `local_path` → env `STORAGE_LOCAL_PATH` → `./data/media`. No new dependencies (§5: nothing added).
- **Decision 2 — Per-row driver for library files; current-driver rule for legacy rows:** Every `media_assets` row stores its own `driver` (`r2` | `local`); reads always use the row's driver, so switching the driver setting never orphans library files. Favicon + payment evidence are legacy rows with no driver column — they follow the CURRENT driver setting, so switching drivers orphans previously stored favicon/evidence objects until switched back. The Settings → Storage page warns about this explicitly and the switch is audit-logged (`storage.settings.updated`). No migration of existing objects in this batch. The favicon + both evidence routes were rewired onto `resolveStorageDriver` (same 503 fail-closed rule now applies uniformly — the admin evidence route previously had NO fail-closed check; the resolver now enforces it there too).
- **Decision 3 — Allowlist, not "whatever" (API spec §18.13):** Accepted types: images PNG/JPEG/WEBP/GIF/SVG, video MP4/WebM, audio MP3/WAV/OGG, PDF, ZIP, plain text + CSV. Anything else → 415; oversize → 413. Every type gets MIME + magic-byte validation (`apps/api/src/platform/storage/media-validation.ts`: `verifyMediaBytes`, `MAX_MEDIA_BYTES` = **100 MB** per library file — the 5 MB evidence cap is untouched, it is a different flow). SVG is XML: the file is sanitized FIRST (script, `on*` handlers, `javascript:` hrefs, `<foreignObject>`, DOCTYPE stripped), then required to parse with `<svg>` as the root; served with `Content-Security-Policy: sandbox` and `X-Content-Type-Options: nosniff`, previewed via `<img>` only — never rendered inline as HTML. Display filenames keep spaces (they are what the user searches for); only path separators / control chars are replaced — the STORAGE key is sanitized separately (`media/YYYY/MM/<uuid>-<sanitized>`, server-generated only). Width/height are parsed best-effort from PNG/JPEG/WEBP/GIF headers (SVG from width/height/viewBox).
- **Decision 4 — Media library model (migration 0012, `db/schema/media.ts`):** `media_assets` (id uuid PK, object_key unique, driver check `r2`|`local` default `r2`, original_filename varchar 255, mime_type, byte_size bigint > 0, checksum_sha256, width/height nullable ints > 0, folder varchar 120 default `''`, tags text[] default `'{}'`, uploaded_by_user_id → users SET NULL, created_at/updated_at; indexes folder+created desc, mime+created desc, created desc) + `storage_settings` singleton (id `'default'`, driver, local_path nullable, updated_at) + permissions `media.view` / `media.manage` (deterministic UUIDs `…130`/`…131`, continuing the 0003 sequence). Grants: super_admin + admin + support_staff get both (media is working content, like tickets/leads); read_only gets view only; finance_manager / license_manager / product_manager / marketing_manager get none. `storage_settings` is NOT in the DrizzleStore snapshot — direct drizzle access, same pattern as `general_settings`. Delete order: row first, then object (best-effort) — a failed object delete leaves an orphaned invisible object; the reverse order would leave a user-visible row pointing at nothing.
- **Decision 5 — No thumbnails in this batch:** No image-processing dependency exists in the Worker runtime, and none was added (§5). The grid previews images via the authenticated content URL (browser-scaled, `loading="lazy"`). A thumbnail pipeline is a follow-up, not invented here.
- **Decision 6 — Server-side search, same hard rule as PLAN §29 (API spec §18.13):** Library list `?q=` filters server-side over the FULL `media_assets` dataset (filename ILIKE + tags ILIKE via `EXISTS … unnest(tags)`); `kind` / `folder` / `mime` are server params too; `limit` (default 50, max 100) caps AFTER filtering; `offset` pages. Upload is multipart `FormData` (`POST /api/v1/admin/media`, `request.formData()`); favicon + payment evidence stay JSON+base64 (their established pattern) — only the storage driver underneath changes. Contract in `packages/contracts/src/domains/media.ts` (`MediaAssetView` incl. `content_url`, `MediaListQuery/Response`, rename/move/tags bodies, `StorageSettingsView/UpdateBody`).
- **Decision 7 — Media picker (shared `MediaPicker`, `apps/admin/src/components/media-picker.tsx`):** One dialog usable from ANY upload spot — browse/search the library (same server-side search, 250ms debounce) AND upload new from the same place (button + drag-drop, mime guard enforced in the picker because drag-drop bypasses the input `accept`), then pick. The picker returns the picked ASSET; callers that keep their own upload endpoint (favicon, payment evidence) fetch the bytes back via the authenticated `content_url` (`fetchMediaFile` → `File`) and send them through their unchanged base64 endpoint — so the favicon keeps its own key (`branding/favicon-<sha256>`) and evidence keeps `payment-evidence/<orderId>/<uuid>`, with no model change. The picker respects each spot's accepted types via an exact `mimes` prop (favicon: PNG/SVG only — ICO is NOT a library type, direct upload still accepts it; evidence: PNG/JPEG/WEBP/PDF). Direct upload stays available inside the picker. Wired into BOTH existing upload spots (general-settings favicon, payment-review evidence). The shared `apiRequest`/`rawApiRequest` now skip the JSON Content-Type for FormData bodies (browser sets the multipart boundary) — previously every body got `application/json`.
- **Decision 8 — Library UI (Neon system, `apps/admin/src/sections/media-library.tsx`, route `/media`, Product group, `media.view`, lucide `Images`):** Grid + list toggle, type filter chips (All + Images/Video/Audio/Documents/Archives/Other), server-side search, folder sidebar (sticky 200px; horizontal chip row < 900px), preview detail Drawer (image / video / audio players, icon + metadata otherwise), bulk select + delete (confirm), upload dialog (multi-file, folder + tags), rename / move-to-folder / edit-tags dialogs, empty states stay empty (different copy when filtered vs empty library). Settings → Storage page (`apps/admin/src/sections/storage-settings.tsx`, `users.manage`, `SETTINGS_CATEGORIES` General group, lucide `HardDrive`): driver Select (R2 recommended / Local), local-path input (Local only), the orphan-on-switch warning, Save disabled when unchanged. One delimited `/* media-library: start/end */` tokens.css block (folder ladder uses surface-hover / nav-active-bg — active strongest, per the 2026-11-16 nav rule).
