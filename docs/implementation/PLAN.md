- **better-auth 1.7.23 ships the twoFactor plugin** (`better-auth/plugins/two-factor`: `twoFactor`, `twoFactorClient`; endpoints `/two-factor/enable`, `/two-factor/verify-totp`, `/two-factor/verify-backup-code`, `/two-factor/generate-backup-codes`, `/two-factor/disable`, `/two-factor/get-totp-uri`; options `issuer`, `totpOptions {digits, period}`, `backupCodeOptions`, `skipVerificationOnEnable`, `twoFactorCookieMaxAge` default 600s). ### Decisions recorded before coding (spec-grounded, not invented)
- **Upload transport:** multipart `FormData` for the media library (`POST /api/v1/admin/media`, `request.formData()`), per the batch brief. The favicon + payment-evidence flows stay JSON+base64 (their established pattern) — no churn, only the storage driver underneath them changes.
- **Allowlist, not "whatever":** the owner said "whatever", but Security §4.9 requires MIME + magic-byte validation for every accepted type, and an open-ended accept-all cannot be validated. Allowlist (ADR-0011): images PNG/JPEG/WEBP/GIF/SVG, video MP4/WebM, audio MP3/WAV/OGG, PDF, ZIP, plain text + CSV. Anything else → 415. SVG is XML: must parse as SVG and is sanitized (no `<script>`, no `on*` handlers, no `javascript:` hrefs, no `<foreignObject>`); served with `Content-Security-Policy: sandbox` and never rendered inline as HTML (preview via `<img>` only).
- **Size cap:** library cap **100 MB** per file (`MAX_MEDIA_BYTES`); the 5 MB evidence cap is untouched (evidence is a different flow with its own limit).
- **Driver rule:** media rows store their own `driver` (`r2` | `local`) — reads always use the row's driver, so a driver switch never orphans library files. Favicon + payment evidence (legacy rows with no driver column) follow the CURRENT driver setting; switching drivers orphans previously stored favicon/evidence objects until switched back — the Storage page warns explicitly and the switch is audit-logged. No migration of existing objects in this batch.
- **No thumbnails:** no image-processing dependency exists in the Worker runtime; the grid previews images via the authenticated content URL (browser-scaled, `loading="lazy"`). A thumbnail pipeline is a follow-up, not invented here.
- **Permissions:** `media.view` / `media.manage` (migration 0012, deterministic UUIDs continuing the 0003 sequence). Grants: super_admin + admin + support_staff get both (media is working content, like tickets/leads); read_only gets view only; finance/license/product/marketing get none.
- **Search rule (owner hard rule, PLAN §29):** the library list `?q=` filters server-side over the FULL `media_assets` dataset (filename + tags), `limit` caps AFTER filtering; type + folder filters are server params too.
